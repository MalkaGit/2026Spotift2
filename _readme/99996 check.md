## 1. Docker – API + MySQL (+ Frontend) in containers

- **Goal (what we want to learn):** Run the backend (API + MySQL) in containers using a Dockerfile and docker-compose, so deployment uses a reproducible environment and the server does not need local Node or MySQL installed.
- **On screen (how we use it):**
  - **During development:**
    - Frontend runs locally from `clientWorkspace-AI` (e.g. `npm run dev` in the React app).
    - Backend API runs locally from `serverWorkspace/app-rest-api` (e.g. `npm run dev`).
    - Database is your existing **local MySQL** instance.
    - Data flow: **local frontend → local API → local MySQL**.
  - **Before deployment (Docker):**
    - Backend API runs inside a Docker container (image built from the repo).
    - MySQL runs in a Docker container with a data volume.
    - Frontend is built (static assets) and served from its **own Docker container** (e.g. Nginx serving the React build) and calls the API container's URL.
    - Data flow: **frontend container → API container → MySQL container**.
- **DB updates (when we add tables):** We keep using migrations/SQL scripts in the repo. When schema changes, we run the same migrations against the MySQL container (via CLI or `docker exec`); the data/schema live in a volume so they persist between container restarts.
- **User story:** As a developer, I run the whole app the same way when I deploy so the server environment is consistent.
- **CV line:** Containerized Node API and MySQL with Docker Compose.
